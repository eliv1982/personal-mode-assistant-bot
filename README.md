# ModeMate AI

**ModeMate AI** — Telegram LLM-ассистент с ролевыми режимами, кратковременной памятью диалога и учётом стоимости запросов к OpenAI.

[![Tests](https://github.com/eliv1982/personal-mode-assistant-bot/actions/workflows/tests.yml/badge.svg)](https://github.com/eliv1982/personal-mode-assistant-bot/actions/workflows/tests.yml)

Личный AI-помощник в Telegram для ежедневных задач: планирование дня, принятие решений, редактирование текстов, обучение и генерация идей.

---

## Что делает ModeMate AI

Бот общается через OpenAI и поддерживает **5 специализированных режимов**. Каждый режим — отдельный системный промпт из `prompts.json`, настраивающий поведение AI под конкретную задачу. Бот запоминает контекст диалога (краткосрочная память по каждому чату), ведёт журнал расходов токенов и позволяет в один клик посмотреть детали любого запроса.

**Стек:** Python, [aiogram](https://docs.aiogram.dev/) (Telegram Bot API), [OpenAI Python SDK](https://github.com/openai/openai-python), long polling, локальное хранение в JSON.

**Статус:** рабочий pet-проект для личного использования. CI зелёный, 130 тестов, hardening по персистентности/сети/конфигурации выполнен (см. [Тестирование и CI](#тестирование-и-ci)).

## Режимы

| Режим | Ключ | Описание |
|---|---|---|
| 📅 Планировщик дня | `daily_planner` | Мягко раскладывает задачи по приоритетам, строит реалистичный план без токсичной продуктивности |
| ⚖️ Помощник по решениям | `decision_helper` | Сравнивает варианты, показывает плюсы/минусы, риски и нейтральный вывод |
| ✍️ Редактор текста | `text_polisher` | Улучшает письма, посты и формулировки: яснее, мягче, увереннее, короче |
| 🎓 Учебный помощник | `learning_coach` | Объясняет темы, код и домашние задания простым языком, по шагам и с примерами |
| 💡 Лаборатория идей | `idea_lab` | Генерирует идеи для проектов, названий, UX, фич и улучшений |

Режимы хранятся в `prompts.json` и легко редактируются без изменения кода. Файл валидируется при старте бота — при отсутствующем/битом `prompts.json` или незаполненном `system_prompt` бот не запустится (fail-fast вместо тихой деградации).

## Как это работает

### Память

- Каждый чат (`chat_id`) хранит независимую историю в `data/memory.json`.
- Для каждого `chat_id` сохраняются: выбранный режим и последние N сообщений (N = `MEMORY_LIMIT`; сообщения user и assistant считаются по отдельности, не парами).
- В OpenAI передаётся: `system_prompt` выбранного режима + последние N сообщений + новое сообщение.
- `/reset` очищает историю, но **не сбрасывает** режим и **не трогает** статистику расходов.
- Запись в память происходит только после того, как ответ реально доставлен в Telegram — недоставленный ответ в историю не попадает.
- Файл памяти создаётся автоматически при первом обращении. Если файл повреждён (битый JSON / не тот тип верхнего уровня) — он переносится в quarantine-копию (`*.corrupt.<timestamp>`), инцидент логируется, а бот продолжает работу с пустой памятью для этого файла.

### Форматирование ответов

Все системные промпты содержат правила Telegram-friendly форматирования:
- Без Markdown-заголовков (`#`, `##`, `###`)
- Без Markdown-таблиц
- Блоки кода только если пользователь явно просит написать/показать код
- Для списков: символ `•` или цифровая нумерация (`1. 2. 3.`)

Ответы дополнительно прогоняются через санитайзер (`text_utils.sanitize_ai_text`) и отправляются без `parse_mode`, чтобы случайные Markdown-артефакты в ответе модели не превращались в битую разметку. Длинные ответы автоматически режутся на несколько сообщений по лимиту Telegram (4096 символов).

Служебные сообщения бота (команды, статистика) формируются кодом и используют безопасный HTML.

### Usage Log и статистика

После каждого LLM-ответа под сообщением появляется кнопка **📊 Детали запроса**.

Нажатие показывает:
- Режим и модель
- Дата и время запроса
- Входящие / исходящие / всего токенов
- Стоимость в USD и ₽
- Курс ЦБ РФ и дата курса
- Предупреждение `⚠️ fallback`, если ЦБ был недоступен

Все записи сохраняются в `data/usage.json` (без текста запросов и ответов — только метрики). Если запись статистики не удалась (ошибка записи на диск), ответ всё равно доставляется пользователю, но без кнопки деталей — уже потраченный на OpenAI запрос не теряется молча.

#### `/stats` — агрегированная статистика

Команда `/stats` показывает по текущему `chat_id`:

| Метрика | За всё время | Сегодня | За месяц |
|---|---|---|---|
| Запросов | ✓ | ✓ | ✓ |
| Токенов | ✓ | ✓ | ✓ |
| Стоимость USD | ✓ | ✓ | ✓ |
| Стоимость ₽ | ✓ | ✓ | ✓ |

Рублёвые значения в `/stats` пересчитываются по актуальному курсу ЦБ РФ на момент запроса статистики.

**Важно:**
- Стоимость **примерная** — считается по ценам из `.env` (`OPENAI_INPUT_PRICE_PER_1M`, `OPENAI_OUTPUT_PRICE_PER_1M`), а не по реальному биллингу OpenAI.
- Рубли считаются по курсу ЦБ РФ на дату формирования статистики, а не по историческим курсам на момент каждого запроса.
- `/reset` не сбрасывает статистику. Для сброса используйте `/resetstats` (с подтверждением inline-кнопками).

## Cost Tracking

```
input_cost  = input_tokens  / 1_000_000 × OPENAI_INPUT_PRICE_PER_1M
output_cost = output_tokens / 1_000_000 × OPENAI_OUTPUT_PRICE_PER_1M
total_usd   = input_cost + output_cost
total_rub   = total_usd × usd_rub_rate
```

**Курс USD/RUB** берётся из официального XML-фида ЦБ РФ (`https://www.cbr.ru/scripts/XML_daily.asp`) и кэшируется в памяти процесса примерно на час, чтобы не дёргать ЦБ на каждый запрос.

Если ЦБ недоступен при обновлении курса:
1. используется последний успешно полученный курс (даже если он немного устарел) — это всё ещё реальные данные ЦБ, а не fallback;
2. и только если ни разу не удавалось получить курс с момента запуска бота — используется `USD_RUB_FALLBACK` из `.env` (по умолчанию `100.0`), а в деталях запроса появляется пометка `⚠️ fallback`.

## Установка и запуск

**Тестируемые версии Python:** 3.11 и 3.12 (см. CI-workflow `.github/workflows/tests.yml`).

```bash
# 1. Клонировать репозиторий и перейти в папку проекта
git clone https://github.com/eliv1982/personal-mode-assistant-bot.git
cd personal-mode-assistant-bot

# 2. Создать и активировать виртуальное окружение
python -m venv venv
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Создать .env из шаблона и заполнить своими значениями
cp .env.example .env

# 5. Запустить бота
python main.py
```

### Конфигурация

Все переменные окружения, их назначение и значения по умолчанию описаны в [`.env.example`](.env.example) — это источник истины, здесь он не дублируется. Обязательные: `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`. Отсутствие обязательной переменной или некорректное значение (например, нечисловой `USD_RUB_FALLBACK`) останавливает запуск бота с понятной ошибкой, а не молча.

## Безопасность, приватность и ограничения

- Диалоги хранятся **локально в открытом виде** в `data/memory.json`; метаданные использования (токены, стоимость, без текста сообщений) — в `data/usage.json`. Шифрования на диске нет.
- Ключи (`TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`) читаются из переменных окружения (`.env`), который явно добавлен в `.gitignore` и не должен попадать в коммиты.
- Опциональный `ALLOWED_CHAT_IDS` в `.env` ограничивает список `chat_id`, которым разрешено отправлять платные LLM-запросы; если переменная не задана — доступ открыт для любого чата, который найдёт бота.
- Бот получает обновления через long polling, без вебхука и без открытого публичного порта.
- Персистентность на JSON-файлах рассчитана на небольшое личное/одиночное использование, а не на многопользовательскую нагрузку.
- Многопользовательской системы авторизации/ролей нет — `ALLOWED_CHAT_IDS` это простой allowlist, а не RBAC.
- Резервного копирования `data/` и `logs/` не предусмотрено — это ответственность того, кто разворачивает бота.

## Демо

Готовых скриншотов или записи демо в репозитории пока нет — добавлять их сюда без реальных ассетов не стали, чтобы не показывать несуществующий интерфейс. В идеале демо-раздел должен показывать:

1. `/start` — стартовое сообщение
2. `/mode` — inline-кнопки выбора режима
3. Ответ бота с кнопкой **📊 Детали запроса** и разбивку токенов/стоимости
4. `/stats` — агрегированную статистику с курсом ЦБ РФ

## Идеи для развития

Ничего из списка ниже не реализовано — это только направления, которые имеет смысл рассмотреть в будущем:

- **Предложение сменить режим** — если задача лучше подходит другой роли, мягко предлагать переключиться, не делая переключение автоматическим
- **Опциональный лимит расходов** — мягкий бюджетный порог с предупреждением, без жёсткой блокировки
- **Лёгкая персонализация** — обращение, язык ответа, предпочитаемая длина
- **Обратная связь от пользователя** — оценка ответов (👍/👎) для последующего анализа
- **Модель под конкретный режим** — возможность задать свою OpenAI-модель для каждого режима отдельно
- **Упаковка для развёртывания** — Dockerfile / инструкция для деплоя на сервер
